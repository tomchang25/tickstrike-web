# Port 13 Reference Parity Matrix

Parent plan: [Reference Visual Parity and Presentation Polish](port_13_visual_parity_and_polish.md)
Spec: `port_13_01_reference_inventory_and_parity_matrix.implementation_spec.md`

This matrix is the acceptance-target authority for children 13.2 through 13.5. Each row records one reference surface, the evidence it was audited from, what the Web build shows today, the parity decision, and the observable outcome that closes the gap. Requirements stay in the parent plan; this document never restates them.

Decision vocabulary: **Preserve** (keep the shipped behavior as parity), **Reproduce** (author a Web-native presentation to match), **Omit** (intentionally leave out, reason stated), **Defer** (approved product decision, tracked for later).

Evidence is drawn only from the reference checkout under `port-ref/tickstrike/`, the live Web code, and the vendored art packs under `assets/`. Godot scenes and scripts are evidence, never porting contracts.

## Board and terrain (13.2)

Reference board is a 12x12 gameplay grid with a 10x10 centered land plateau and a 1-cell water ring, drawn by an autotiling `TileMapLayer` (terrain-connect, 16px tiles at 8x8 per 128px cell) over a separate water layer, thin grey grid lines, static wall collision, camera zoom 0.65. Evidence: `common/gameplay/grid/grid_arena.gd`, `common/gameplay/grid/grid_terrain_view.gd`, `game/tick_arena/tick_arena.tscn` (grid_size 12x12, starting_land_size 10x10, tile_size 128, Camera2D zoom 0.65), `game/scenes/stages/`.

The Web target diverges from the reference footprint by product decision (widescreen composition, quality-bar captures): an **18x12 grid** holding a **14x8 centered land island** (offset 2,2) with a **2-cell water ring**. The 2-cell ring is the drown border and reuses the existing sea/drown mechanic; the initial island ships clean with no interior obstacles. Each gameplay cell renders as **2x2 tiles** (32px each at CELL_SIZE 64). 13.2 is decomposed into sub-children — 13.2a geometry (core), 13.2b terrain rendering, 13.2c camera, 13.2d decorative frame, optional 13.2e water animation — see the parent plan.

## Entity presentation (13.3)

Player and enemies use a four-direction, four-state directional frame sheet: column = direction (Down/Up/Left/Right), row = visual state. Player renders a body sheet plus a synchronized weapon sheet at scale 5 over 16px cells. Every small enemy — including ranged — uses the same 16px sheet at scale 5 in the reference; role differs only in action-feedback tweens and the authored sheet. No entity uses a drop shadow in the reference. ## Combat feedback and terminal (13.4)

The reference layers ephemeral tween VFX over the semantic combat state: attack windup loops (TILE gold lines / CHARGE white wind), charge start/streak, guarded-hit blue shield spark, guard-break white flash with blue fragments, full-damage red burst with fragments, Smash windup ring + impact burst with 8 fragments, and Major-trigger bursts (Guard Shredder gold shards, Execution collapsing dark burst). The reference source marks these grey-box placeholders explicitly ("interim grey-box presentation can be replaced by real content later"). Per P4, the Web reproductions are authored as sprite animation or industry-grade VFX, not a port of the polygon/line tweens; per P1, telegraph danger cells use authored sprite markers rather than tile-color fills. Damage/stagger tint lives on the sprite. Telegraph countdown badges are painted from grid state, with player-cell countdowns pushed to a head offset.
